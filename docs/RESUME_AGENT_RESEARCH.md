# GuideLab：简历与面试表述

## 一、项目名称

**GuideLab｜面向物理实验的可解释符号回归与可验证 Tool-Agent 平台**

技术栈：Vue 3、FastAPI、PySR、LLM Function Calling、SSE、RAG

一句话定位：面向高校物理实验数据，利用 PySR 从观测数据中发现可解释方程，并由 Tool-Agent 完成分析工具选择、参数生成、异常修复和结果解释。

## 二、简历项目经历

### 推荐版（四条）

- 面向高校物理实验数据，基于 PySR 构建可解释符号回归流程，在 `+、-、×、÷、sin、cos、exp、log` 等算子构成的表达式空间中搜索候选方程，并支持种群规模、迭代次数和最大表达式复杂度等参数配置。
- 联合展示候选方程的拟合损失、PySR score 与表达式复杂度，并基于 R²、归一化 RMSE、MAE、有效覆盖率和复杂度风险生成分项合理性诊断，明确区分样本内拟合证据与待人工核验的物理合理性。
- 设计声明式 Skill 与 Function Calling 驱动的 Tool-Agent，使模型按任务选择 PySR 拟合、状态查询和任务取消工具；服务端通过 Skill 白名单、JSON Schema 校验和服务端数据上下文保证调用边界。
- 实现参数错误反馈、重复失败阻断和 SSE 可追溯执行链路；构建 40 例三策略消融评测集，Skill 与结构化执行反馈使端到端成功率由 **82.5% 提升至 100%**，10 个恢复案例的 3 次重复实验达到 **96.7%**。

### 一页简历压缩版（三条）

- 基于 PySR 构建面向物理实验的可解释符号回归流程，通过算子空间和复杂度配置搜索候选方程，并结合 R²、归一化 RMSE、有效覆盖率与复杂度风险评价样本内拟合合理性。
- 设计基于声明式 Skill 与 Function Calling 的 Tool-Agent，实现 PySR 任务的参数生成、提交、查询与取消，以及参数错误反馈、重复失败阻断和 SSE 调用轨迹。
- 构建 40 例三策略 Tool-Agent 消融评测集；Skill 与结构化执行反馈使端到端成功率由 **82.5% 提升至 100%**，恢复案例 3 次重复实验达到 **96.7%**。

## 三、30 秒口述版

GuideLab 是一个面向大学物理实验的智能分析平台。针对传统黑盒回归只能给出预测、难以揭示变量显式关系的问题，我使用 PySR 从实验数据中搜索可解释方程，并比较候选方程的拟合损失、搜索得分和表达式复杂度。进一步地，我把 PySR 封装成 Tool-Agent 可调用的计算工具，让模型根据实验任务生成参数、提交拟合并解释结果；如果参数错误，系统会把结构化错误反馈给模型，引导下一轮修正。为了验证可靠性，我构建了 40 例消融评测集，Skill 与执行反馈将端到端成功率从 82.5% 提升到 100%，恢复案例重复实验达到 96.7%。

## 四、1 分钟面试介绍

这个项目关注两个问题：第一，怎样从物理实验数据中发现可解释的数学关系；第二，怎样让大模型可靠地调用分析工具，而不只是生成一段自然语言。

在算法侧，我选择 PySR 符号回归。它不是预先指定线性或多项式形式，而是在给定算子空间内搜索解析表达式。系统允许配置种群规模、迭代次数和最大复杂度，并保留多个候选方程，比较 loss、score 和复杂度，避免只选择一个误差低但非常复杂、缺乏物理意义的表达式。

在 Agent 侧，我把拟合、任务查询和取消封装成带 JSON Schema 的工具，并通过 Skill 限制不同任务可使用的工具。模型生成参数后由服务端校验，执行结果再以 Tool message 返回模型。如果发生越界参数或服务异常，模型会收到结构化错误并进入下一轮修正；相同失败调用会被阻止，执行过程通过 SSE 留下可追溯轨迹。

最后我做了三组消融实验。结果表明 Skill 与结构化反馈相对只提供 Tool Schema 有明显提升，但额外的显式 repair prompt 没有继续提高结果。因此我的结论是结构化任务知识和执行反馈有效，而不是笼统宣称“自我反思一定有效”。

## 五、面试高频问题

### 1. 为什么选择 PySR，而不是线性回归或神经网络？

物理实验不仅关心预测精度，还希望得到可以阅读、验证和进一步推导的显式方程。线性或多项式回归需要预先假定函数形式，神经网络通常只能给出黑盒映射；PySR 可以在算子空间内搜索多种解析表达式，更适合探索未知变量关系。不过 PySR 搜索成本更高，也可能找到数值上好但物理上不合理的公式，因此系统同时展示复杂度、损失和拟合图，把最终判断留给使用者。

### 2. PySR 的基本原理是什么？

PySR 将数学表达式表示为由变量、常数和运算符组成的表达式树，通过种群搜索、变异和组合产生新的候选表达式，再根据拟合损失与表达式复杂度进行筛选。项目中可以配置迭代次数、种群规模、最大表达式大小和允许的算子集合，从而控制搜索范围与计算成本。

### 3. 你对 PySR 的贡献是什么？是否改进了算法？

我没有修改 PySR 的核心进化搜索算法。我的工作是面向物理实验场景设计符号回归流程：约束可用算子和表达式复杂度，管理搜索参数，保留并可视化多个候选方程，并将 PySR 封装成可调度、可追踪的 Agent 工具。准确表述是“基于 PySR 构建物理规律发现流程”，而不是“提出新的符号回归算法”。

### 4. 怎样评价拟合结果是否合理？

我不会用单一 loss 或一个黑盒总分判断，而是分三层评价。

第一层是数值拟合：检查方程在观测点上的有效覆盖率，并计算 R²、RMSE、归一化 RMSE、MAE、残差偏置以及相对均值基线的改善。系统按公开阈值给出“样本内拟合较强、一般或偏弱”，同时保留每个分项指标。

第二层是复杂度与稳定性：结合候选方程复杂度、搜索上限和样本量给出风险提示。例如复杂度接近 `maxsize` 或样本过少时，即使 R² 很高也提示过拟合风险。当前还没有独立验证集，因此不能把样本内高拟合直接解释为泛化能力。

第三层是物理合理性：核查量纲是否一致、符号和单调性是否符合实验规律、极限行为是否合理，以及换一批数据后方程能否稳定恢复。系统会明确标记这些项目尚未自动验证，需要结合物理先验和重复实验人工复核。因此输出的是“可解释的证据清单”，不是自动证明某个方程就是物理定律。

### 5. 基座模型如何调用 PySR？

每轮将当前 Skill 说明加入 system message，并只暴露该 Skill 允许使用的 Tool Schema。模型通过 Function Calling 返回工具名称和 JSON 参数；服务端先检查 Skill 白名单，再做 JSON Schema 校验。校验通过后，PySR 工具通过内网 HTTP 调用独立计算服务，完整实验数据由服务端上下文绑定，不由模型自行拼接。执行结果以 `role=tool` 放回对话，模型据此继续决策或生成解释。

### 6. 模型生成错误参数或工具执行失败怎么办？

错误会转换为结构化 Tool 结果返回模型，并加入纠错提示，要求它修改参数、改变工具或在无法恢复时安全停止。系统记录失败调用签名，阻止完全相同的失败重复执行；默认最多进行 3 轮工具决策，达到上限后转入不再调用工具的总结阶段。每次调用的轮次、参数、状态、耗时和纠错次数都会通过 SSE 记录。

### 7. 这个项目的科研性体现在哪里？

科研性不在于使用了大模型或 PySR，而在于提出了可检验问题并进行对照实验：固定模型和解码配置，对 `schema_only`、`skill_feedback`、`guided_repair` 三种策略比较工具选择准确率、参数正确率、Recovery@1、不必要调用率和端到端成功率，同时保存逐案例原始轨迹、Bootstrap 区间和失败案例。实验既报告提升，也报告没有支持原假设的结果。

### 8. 实验结果是什么？

40 个独立案例的主实验中，`schema_only` 端到端成功率为 82.5%、Recovery@1 为 30.0%；加入 Skill 与历史执行反馈后两项均为 100%。在 10 个恢复案例、每种策略重复 3 次的实验中，基线恢复成功率为 16.7%，`skill_feedback` 和 `guided_repair` 均为 96.7%。两种增强策略没有差异，说明显式 repair prompt 在当前样本上没有可测的额外收益。

### 9. 这些结果有什么限制？

实验只使用一个模型；40 个独立案例只运行一次，重复实验则只覆盖恢复类案例；评测只检查模型生成的 Tool call，没有真实执行耗时较高的 PySR 任务。另外，`skill_feedback` 同时加入 Skill 与错误反馈，因此不能把增益分别归因给某一项。结果适合作为项目级验证，不能外推成跨模型或大规模论文结论。

### 10. 如果继续研究，你会怎么做？

优先做三件事：其一，将同一物理规律生成不同噪声水平和不同措辞的数据，评估方程恢复稳定性；其二，加入训练/验证划分，与多项式回归等基线比较预测误差、表达式复杂度和真实方程恢复率；其三，将 Skill 和执行反馈拆成独立因子，并扩展到多个模型，解决当前消融中的归因混杂。

## 六、项目贡献边界

可以说：

- 基于 PySR 构建符号回归与候选方程分析流程。
- 设计搜索参数、算子空间和复杂度控制接口。
- 将 PySR 封装为可验证、可恢复、可追踪的 Agent 工具。
- 构建 Tool-Agent 评测集并完成消融与重复实验。

不要说：

- 提出了新的符号回归算法。
- 已实现量纲约束、物理定律自动验证或不确定性估计。
- 证明自我反思机制普遍有效。
- 在大规模、多模型实验中取得显著提升。

## 七、实验数字边界

- 主实验：40 个独立案例 × 3 种策略，共 120 次真实模型调用。
- 恢复实验：10 个恢复案例 × 3 次重复 × 3 种策略，共 90 次真实模型调用。
- 模型：Qwen-Plus；temperature 为 0。
- 两组评测均只读取 Tool call，不真实执行 PySR 工具。
- `skill_feedback` 同时加入 Skill 与历史反馈，其相对基线的提升属于组合效果。
